# speech2ay

**Harmonic AY synthesis for speech and sound effects.**

**[Run TS2068 Audio Lab in your browser](https://jon0x0.github.io/speech2ay/)**

Compare ten codecs across four samples, with animation and spectrum displays.
Powered by [TSRun](https://github.com/josef-jelinek/TSRun).

## Why speech2ay?

Playing recorded speech on an AY-equipped computer presents a tradeoff:
digitized playback needs frequent, precisely timed volume writes and substantial
storage, while the chip has only three tone channels and a shared noise
generator for synthesis. We want recognizable speech and sound effects that
leave enough CPU time and memory for the rest of a game or application.

`speech2ay` analyzes short sections of a recording, estimates their pitch, and
fits combinations of AY square-wave harmonics to their frequency spectrum.
A band/noise model handles less periodic sounds, including unvoiced speech.
It produces settings for one, two, or three AY channels. The optional `ayfit`
tool searches for better register settings using synthesized audio to compare
waveform and spectral errors against the recording.

The result replaces thousands of sample writes per second with a small stream
of synthesizer updates. The supplied TS2068 player updates about 60 times per
second, uses roughly 3% of the CPU without animation, and stores about 842 bytes
per second before additional storage compression. This makes speech alongside
gameplay, animation, and input processing practical. Harmonic fitting accounts
for the extra harmonics generated by AY square waves, rather than assuming each
channel produces a pure sine wave. It still trades fidelity for efficiency:
voices can sound robotic, and some effects or transients suit digitized playback
better. The comparison tools let you hear that tradeoff for your own recordings.

Read [Speaking with the TS2068](./docs/speaking-with-the-ts2068.md) for the fuller
explanation, audio-quality compromises, CPU budgets, and compression comparisons.

## Tools and supported hardware

The AY conversion algorithms are useful beyond a single computer. The bundled
Z80 runtimes, timing, TAP/DCK exporters and Audio Lab demos currently target the
Timex Sinclair 2068. Other machines need their own playback integration and
clock/timing adaptation; the CLI currently packages TS2068 outputs.

This is a separate project from Audio2AY. Upstream Audio2AY can optionally be
used as an external comparison converter.

Install with `python -m pip install .` or run the Python scripts from this
directory. Installed commands are `speech2ay`, `audio2aydac`, `ayfit`, and
`aydemo`. See [development](CONTRIBUTING.md) and [license status](LICENSE.md).

Four small Python commands for speech **and sound effects**, sharing documented Z80 players:

| Command | Purpose |
|---|---|
| `audio2aydac.py` | Packed AY4 at 5/6 kHz and DPCM3 at 6 kHz |
| `speech2ay.py` | Pitch/harmonic spectral fitting with 1, 2 or 3 AY channels |
| `ayfit.py` | Optional stateful waveform/spectrum parameter search using Ayumi |
| `aydemo.py` | Keyboard-selectable multi-sample, multi-codec demonstrations |

Requires Python 3.10+, `pip install -r requirements.txt`, and Pasmo. Set
`PASMO` to the assembler executable or pass `--pasmo PATH`. On Windows, an
extensionless Linux Pasmo path is invoked through WSL; native `.exe` paths
run directly. No game repository, numbered filenames, WAV assets or ROM
files are required to convert audio. Input is nonempty 8/16-bit PCM WAV,
mono or multichannel (averaged to mono). Supply multiple paths or directories.

```sh
python audio2aydac.py clips --codecs ay4-5k ay4-6k dpcm3-6k --format tap dck --out build/dac
python speech2ay.py voice.wav effect.wav --channels 2 --format bin --origin 0x9000 --out build/harm
python speech2ay.py clips --channels 3 --format bin --separate-data --data-origin 0xd000 --out build/library
python ayfit.py voice.wav --ayumi /path/to/ayumi --passes 3 --objective joint --format tap dck --out build/fit
python aydemo.py clips --format tap dck --out build/demo
python aydemo.py clips --audio2ay /path/to/audio2ay.exe --format dck --out build/compare
```

All commands accept `--low`/`--high` cutoff frequencies. `ayfit` additionally
requires GCC (`--gcc`) and the external Ayumi source directory. Its amplifier
approximation exposes `--feedback-cutoff` and `--feedback-gain`; see the article.
Use `--help` on each utility for options. The Audio2AY adapter uses the upstream
two-byte period/volume format, three channels, no arpeggio, calibrated AY clock.

Read the [command-line guide](docs/command-line-guide.md) for copy-and-paste
examples for every utility, optimizer options, separate data, and the exact
four-sample comparison build.

`aydemo --format dck` builds one expanded 64K comparison cartridge. **O/P**
selects the sample, **Q/A** selects the codec, and **Space** plays. The original
small font has 16-pixel row spacing; each codec displays stored ROM bytes.
Lossless storage compression is expanded before playback; stream byte counts
are also recorded in the manifest.
A sine wave moves during playback. Add `--optimize 1 2 3 --ayumi PATH` for
optimized versions of every sample and `--audio2ay PATH` for upstream results.
Add `--spectra --ayumi PATH` for an **S**-key view comparing original and
modeled whole-clip FFT spectra. FFTs are calculated offline; playback runs
unchanged. See the command guide for modeling assumptions and validation status.
Use `--sample-profile Laser=berzerk` to reproduce the game's effect conversion
for that sample's harmonic/optimized entries; other entries keep their profile.
Release keys between actions. Oversized collections report a capacity error.
The comparison pairs AY entries by channel count: harmonic1, optimized1,
harmonic2, optimized2, harmonic3, optimized3, followed by Audio2AY.

TAP and the individual converter demos use the smaller layout: Q/A selects
the combined sample/codec entry. Large collections in that layout become
numbered volumes, listed in `index.json`. Their older animation differs from
the expanded cartridge. Neither animation is a measured oscilloscope.

## Generated files

- `module.bin`, `module.asm`, `module.sym`: callable player, rebuilt at `--origin`.
- `data.bin`: concatenated raw payloads; load separately only with `--separate-data`.
- `manifest.json`: API addresses, payload offsets, counts, durations and source hashes.
- `api.inc`: entry-point constants for assembly callers.
- `runtime.asm`: reference playback source, without an ORG or data.
- `demo.tap`: autoloading BASIC loader plus demo machine code.
- `demo.dck`: ROM-only chunks 4/5, contiguous `$8000–$BFFF`.
- `comparison.dck`: expanded `aydemo` cartridge, all eight ROM chunks;
  resident code in chunk 4, bank-loaded payloads in the other seven chunks.
- `picorom.bin`: flat 64K physical address image; ROM payload at offset `$8000`,
  unused chunks FF-filled. **Do not program the DCK header onto PicoROM.**
- `player.asm/.bin/.sym`: the last assembled artifact (demo for TAP/DCK builds).

Multiple formats get separate directories; TAP has no cartridge paging/header.
Separate-data mode currently targets callable **binary** output, not an
autoloading multi-file tape loader. The host program owns file loading.
The expanded comparison has its own native RAM staging layout. See
[integration](docs/integration.md) before embedding or changing addresses.

Read [Speaking with the TS2068](./docs/speaking-with-the-ts2068.md) for quality,
CPU budgets and compression comparisons. [Validation](docs/validation.md)
distinguishes assembled, emulator-tested and physically untested behavior.

## Provenance

The DSP, harmonic estimator and optimizer are extracted and generalized from
this project's tested speech experiments. They do not import their originals.
The packed playback/export layer and DPCM3 stream format are new; DPCM3 is
**not binary-compatible** with earlier Berzerk speech packages. The optimizer
worker uses external Ayumi; its license remains with that dependency. Upstream
Audio2AY is optional and not bundled. The browser demo includes encoded sample
recordings; see [credits and provenance](web/THIRD-PARTY.md). Original WAVs and
system ROMs are not bundled. No new license is asserted over existing
project code; establish redistribution terms before publishing to third parties.

One- and two-channel harmonic/optimized entries in the comparison demo show
compact-stream byte estimates with an asterisk; unstarred counts are actual
stored payload bytes. The common playback format is unchanged. See the
[storage explanation](./docs/speaking-with-the-ts2068.md#smaller-one--and-two-channel-streams)
for the calculation and actual-versus-estimated counts.
